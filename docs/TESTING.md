# اختبار NEW_VOCR

## ملفات tests وخدمة الموديل

`tests/` ملفات تطوير لا تُنفذ مع Docker أو `run_pipeline.sh` ولا يستوردها السيرفر.
Docker Compose يستخدم صورة vLLM الموجودة، ويربط مجلد الموديل وserver/start.py؛
لا يوجد تحميل لمجلد tests إلى خدمة الموديل. `pytest` ضمن اعتماديات dev فقط.

لتجهيز اختبارات التطوير اختياريًا:

```bash
uv sync --locked
uv run --locked --no-sync pytest -q tests/test_new_vocr.py tests/test_merged_contract.py
```

ملفات الاختبار الصناعية تستخدم بيانات وردودًا مصطنعة، وبعضها سيرفر HTTP محليًا.
الاختبارات التي تحتاج PDF تاريخيًا أو snapshots غير موجودة قد تتخطى التنفيذ أو
تحتاج توفير ملفاتها الأصلية. اختبارات حفظ Linux ومجموعة تشغيل workflow قد تحتاج
بيئة Linux المناسبة؛ الاختبارات لا تثبت دقة Qwen على الكتالوجات الحقيقية.

## تحقق النسخة قبل التسليم

نراجع إزالة العمودين من CSV الفردي والمجمّع، واستمرار الترقيم عبر الصفحات مع
تعدد المكونات، وحدود ميزانية الكشف والمتابعات والإعادة، والحفاظ على override
اليدوي، وتشغيل LangGraph بالعمليات المنفصلة، وعدم تغير البرومبتس وCompose.
نتائج التحقق المحلية النهائية مسجلة في release-validation.json داخل المشروع.

## اختبار DGX التالي

1. استخدم `.env` الموجود وراجع أن الخدمة healthy. لا تحتاج تغيير مسار الأوزان
   أو max-num-seqs=64 أو إعدادات GPU لتحميل هذه النسخة.
2. اختر صفحات قليلة من الملفات الخمسة، بما فيها أسماء بلا أكواد، وأكواد بلا أسماء،
   وصفحات كثيفة، وجدول/أدوات لضبط الكشف. لا تخلط نفاد الطلبات بخطأ تعرف.
3. راجع صور المصدر والقص وoverlays مع CSV وMarkdown؛ تحقق من رقم PDF الأصلي.
4. بعد قبول العينة، شغّل PDF كاملًا. الأمر الأساسي يعالج ملفًا واحدًا؛ عند اختبار
   الخمسة شغّل الملفات بالتتابع، بحد 32 داخل الملف.
5. قارن الزمن والتغطية على نفس الصفحات والإعدادات. لا تعتبر نجاح التنفيذ إثبات دقة.

عينة الجودة الصغيرة قد لا تشغل 32 طلبًا بالفعل؛ قياس التشبع يحتاج عدد صفحات كافيًا.
تجهيز النسخة الأول كان محليًا. بدأ لاحقًا اختبار فعلي على DGX كما هو موضح أدناه.
## اختبار إضافات علاقات التصنيع

`tests/test_fabrication_relations.py` يختبر حفظ البرومبتات الأصلية، علاقات التكبير
والقطاعات، رفض العلامات المكررة والبدائل المختلفة، والتحقق من بكسلات المؤشر.
هذه اختبارات محلية ببيانات مصطنعة وليست قياسًا لدقة Qwen على ملفات الكتالوج.
قياس الدقة والزمن الفعليين يحتاج تشغيل العينة على DGX بمجلد output جديد.

## حالات الكتالوج العامة

`tests/test_mx_general.py` يختبر المطابقة الحرفية للأكواد، اختلاف النظام والقسم
والبديل، غياب النطاق، تضارب الأسماء، تغيّر صورة المصدر، صفوف Reference المجمعة،
الاسم فقط، التخطي، ترتيب التسليم، وعلاقات Detail الرقمية التي لا تدمج العضوية.
يتضمن تسليمًا فعليًا باسم مأخوذ من صفحة جدول أخرى مع أدلة المصدر.

اختبار المراحل السبع في `test_leader_correction.py` يشغّل PDF صناعيًا عبر المراحل
نفسها مع ردود موديل مصطنعة؛ يشمل مفتاح شرح مرقمًا يصل بالكود والاسم إلى CSV.
اختبارات compact تثبت حفظ النطاق وصورة قراءة الجدول. هذه ليست قياسات دقة Qwen.

على Windows فقط، fixture الاختبار `portable_checkpoint_io` يسمح باختبار OCR بعد
حفظ الملف واستبداله عندما تغيب O_DIRECTORY؛ لا يعدّل كود الحفظ الإنتاجي ولا
يثبت متانة directory-fsync الخاصة بـLinux. اختبار ذلك يكون على DGX.

قبل اختبار PDF كامل راجع: 40 و48 و49 و52–53 و99 و110 و116 و125 و134 و142
و190 و192–195 و202 و224 و228 من العينة التي استندت إليها المراجعة. الأرقام هنا
لا تُستعمل في منطق الإنتاج. راجع أيضًا مصدرًا آخر بأكواد وعناوين مختلفة لإثبات
التعميم، وسجّل الرفض/النقص كما تسجّل النجاح. إعدادات الموديل لا تتغير للاختبار.

اختبارات سياق OCR الإضافية في `test_mx_general.py` تتحقق من تحويل نقاط PDF إلى
إحداثيات صورة الطلب، وتحويل crops المدورة، واستبعاد spans المقصوصة أو المستثناة،
وإلزام scope في schema المرسل مع قبول الرد القديم، وتمرير مهلة 600 ثانية عند
طلبها صراحة، وإثبات عبارة داخل banner من مواضع حروف PDF الحقيقية.

## تجربة DGX وإصلاح عقد الرد

التجربة الأولى على 16 صفحة MX وصلت للكشف والقص والأكواد، لكنها سجلت فشلًا في
التعرّف ونقصًا في إثبات خطوط الإشارة؛ لا تُعد نتائجها قياس نجاح أو عدًّا صحيحًا.
أوقفت أثناء OCR المؤجل مع حفظ نواتجها. الإصلاح يُلزم المودل بإرجاع حقول التقييم
صراحة، ويقيد اسم المكوّن ببيانات النص دون category، ويقيد مراجعة التغطية بعدد
ومعرفات المرشحين الفعليين. التحقق الهندسي والتحقق النهائي من الرد كما هما.

بدأت تجربة `mx-cases16-v2-20261029` في `/home/domapp/Z_AiWork/NEW_VOCR/output_dgx16_v2`
بنفس الصفحات وconcurrency=16. بدء التشغيل ليس اعتمادًا لجودة نواتجه؛ راجع حالة
التشغيل وخطوط الإشارة والمخرجات النهائية قبل الاعتماد. لم تتغير إعدادات Docker.
